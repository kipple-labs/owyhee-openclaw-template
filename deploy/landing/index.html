Owyhee

Deploy an AI agent that can't run wild.
One click. Your cloud. Governed from minute one.

This stands up a hardened OpenClaw agent in your own cloud. Every tool it touches — and its model calls too — go through Owyhee: permission-gated, budgeted, kill-switchable, and receipted. Your credentials live in Owyhee custody, not on the box. No keys in env files, no open gateway, no wondering what it did overnight.

Pick a deploy path

Railway — one click

The fastest path. Railway builds and runs the image for you; you fill in your email as it deploys — no model key needed.

Deploy on Railway →
Set OWYHEE_DEPLOY_EMAIL when prompted. Add a volume at /data so re-deploys keep the same account. Connect your LLM provider in the console after claiming.

DigitalOcean — droplet with a paste-in script

Create an Ubuntu droplet, and under Advanced options → user data paste the cloud-init below (set your email first — no model key). It installs Docker and boots the agent.

curl -fsSL https://raw.githubusercontent.com/MachinesOfDesire/owyhee-openclaw-template/main/deploy/cloud-init-digitalocean.yml
A native 1-Click Marketplace listing is in review — this script is the same thing, available today.

Hetzner — cloud-init

No native button, but every Hetzner server-create surface takes a cloud-config:

hcloud server create --name owyhee-agent --type cx22 --image ubuntu-24.04 \
  --user-data-from-file deploy/cloud-init-hetzner.yml

What happens after you deploy

The agent boots and provisions a claimable account
Keyed to the email you gave it — no login required at deploy time.
You get a claim link by email
Click it and sign in to bind the account to your login. Unclaimed accounts expire.
Connect tools in the console
Add an MCP server — its credentials go into custody, never onto the box. Grant the agent what it may use.
Watch, cap, or kill it — anytime
Every action is a receipt in Records. Set a spend cap. Suspend the agent and its next action stops cold.
no keys on the box   no open gateway   every action receipted
